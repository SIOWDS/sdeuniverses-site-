# 近邻库（占位者库）· 唯一源

**这个目录是站上近邻库的唯一来源。** 两个 json 都是它的投影，勿手改：

```
tools/nbr/cards_a.py … cards_e.py        ← 唯一源，新卡写这里
        │
        └─ tools/build_nbr.py
              ├→ public/nbr/cards.json          金点子 · 中华智问（/assets/sde-nbr.js）
              └→ public/kb/placeholders.json    碰撞机候选闸（/taste/assets/sde-placeholder-lib.js）
```

## 为什么并成一份源（2026-08-01）

此前是两个库、两套 schema、两批消费者。**两份判据分家一定会漂，而且漂起来是静默的**：
一边补了卡另一边不知道，闸门照样显示「已过闸」，只是它查的那半个库里没有那个人。
并库时实测出 **21 组同作品重复卡**——重复不是冗余，它把召回劈成两半：
查询命中哪一张全看词面的偶然，而两张卡的分离线可能不一样。

## 改卡的规矩

1. **新卡写进 `cards_*.py`，然后跑 `python3 tools/build_nbr.py`。**
   只改生成物会被下一次构建抹掉——这坑踩过两次。
2. **每张卡至少三条别名，至少一条分离线，而且分离线里至少一条是判决性对照预测**
   （同一情形下两者预测相反，并说清怎么读数）。「侧重不同」不算划界。
3. **别名要写「候选可能长成的样子」，不是作者的原话。** 别名表是召回的成败关键：
   《划界者的拇指不在指纹里》检不出卢曼，靠的就是卡上写着「划界者不能安置自己」。
4. **优先入库同向占位者。** 近邻表有自我保护倾向——只点得出能被推开的对立派，
   唯独漏掉同向的那几位，而那才是真正推不开的。
5. **每轮回写。** 评完一篇、切完一批近邻，当天就把新占位者写成卡。
   `frm` 字段记着它从哪一篇回写来的。cards_e 全批就是这么来的。
6. `pid` 是这张卡在原占位者库里的语义 slug，投影回 placeholders.json 时原样用——
   **改了它，碰撞机那边的引用会全部断掉**。

## 三条永不让步的纪律

- **库未命中 ≠ 未被占位。** 只能标〔库未命中〕，不得据以放行。
  这不是谨慎，是实测：评测集里有候选与它的正主一个词都不共享。
- **独立命名空间。** 近邻库与站内文章索引分开，否则检索会先返回自己的文章，
  正好落进「只引自己人＝停在一阶」。
- **通过条件不是「没有近邻」，而是「带着一条可裁决分离线活下来」。**
  只会杀的闸门永不返回健康，只会放的闸门是橡皮图章，比没有更坏。

护栏：`tools/sim_nbr.js`（库与三条纪律）、`tools/sim_nbr_lib.mjs`（并库与卡质量）、
`tools/sim_placeholder_gate.js`（碰撞机那一侧）。**改这里的任何一条，三个都要跑。**
