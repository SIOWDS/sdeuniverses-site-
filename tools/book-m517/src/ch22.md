# 第 22 章　产品线：一本思想如何长出书、课、工具箱、训练营、咨询、软件、API

## 从产品到产品线：单品思维为何在 AI 时代更脆弱

上一章讲的是 AEI 作为新生产单位怎样成立，这一章讲它怎样可能产生收入。先把话说在前面：“财富机器”是本书的说法，它描述的是一台把思想持续变成产品的机器，并不保证这台机器一定赚钱。产品线能不能赚钱，取决于你选的方向有没有人需要、你能不能等到反馈、行业的环境好不好，甚至有时取决于运气。本章讲的是一个结构：思想怎样分裂成多种形态，每种形态各有什么作用。

单品思维是存量时代的思维：做一个好产品，卖很久，慢慢积累。AI 时代更新更快，竞争更密，复制更容易。单品很容易贬值：你刚做出来，别人就能借助 AI 做出相近的版本；你刚形成优势，标准又抬高了；你刚占住一个位置，平台规则又变了。于是单品思维会让人长期不稳：要么追爆款，要么被爆款反噬。

产品线思维换了一个想法：把一套智慧新思想当作种子，让它长出一片林子。林子的好处是抗贬值，一棵树枯了，林子还在，一条收入线下滑，其他线还能撑着；林子也有积累的好处，树多了，生态稳了，传播自然了，用户的黏性高了，反馈丰富了，迭代也快了。本书的判断是：在这样的环境里，倾向于靠产品林子活得久，而不是靠产品烟花，烟花亮一瞬，林子可以长很多年。当然，林子也可能长不起来，这一点后面再说。

## 一个例子：《精益创业》长出的产品线

先看一个现成的例子，看看一本思想怎样长出多种形态。埃里克·莱斯 2011 年出版了《精益创业》，这本书的英文版销量超过一百万册，有 30 种语言的版本。围绕着它，后来长出了年度大会，长出了面向大企业的咨询，通用电气就是其中的一家客户；2017 年他又出了第二本书；2016 年他还创立了一个长期股票交易所，当时尚未获批。

这个例子有两点值得读。第一，它说明一本思想怎样长成多种形态：书是入口，大会是社群，咨询是落到组织里的高价定制，第二本书是继续扩展坐标，交易所则是把同一套想法推向制度层面的尝试。第二，它也提醒我们，长出来不等于都成功。那家交易所在当时还没有获批，这条枝能不能活，是另一回事。所以不要把产品线读成“一本书加上六个衍生品就等于财富”，更准确的读法是：思想一旦有了可复制的结构，就可能向多个方向分裂，其中哪几条枝能活下来，要看条件，也要看运气。

## 七种形态分裂树：书、课、工具箱、训练营、咨询、软件、API

同一套智慧新思想，常见的有七种形态，每一种对应不同的用户、不同的价格、不同的交付方式。你不必一次做完，但要理解它们各自的位置。书是入口产品，建立坐标，形成公共语言。课是理解产品，把读者从“看懂”带到“初会”。工具箱是落地产品，把方法变成可执行的模板。训练营是加速产品，用节律和反馈把“会”变成“成”。咨询是高价定制，把思想落到组织的结构和流程里。软件是规模化交付，把工具箱固化成流程系统。API 是订阅资产，把能力变成可调用的服务，形成长期的关系。

这七种形态其实是一条升级链：从语言到理解，从理解到行动，从行动到习惯，从习惯到系统，从系统到订阅。AEI 的这台机器值得看的地方就在这里：它把意义的发生，转写成可交付、可复制、可升级的结构。但链条越往后，门槛也越高，下面逐一说，每一种形态各卖什么，又各有什么局限。

## 书的位置：入口，建立坐标

不少人把书当成主要的变现方式，写完一本书就盼着财务自由。AI 时代这很难，因为书的复制和替代成本更低，读者的注意力更碎，竞争更激烈。书较合适的位置不是“收钱机器”，而是“坐标确立器”。它做三件事：建立一套公共语言，你用什么词说世界，就把世界组织成什么样；确立你解决问题的坐标系，你按什么标准判断“值得”；形成入口和信任，让读者知道你是谁、在解决什么问题。

书像一扇门，它把读者带进你的坐标系。门本身不一定赚得最多，但没有门，后面的产品线很难成立。书是林子的树干，不是唯一的果实。

## 课的位置：理解，从看懂到初会

课的作用，是把“读懂”变成“可以操作地理解”。很多读者读书时能懂，到做的时候却做不到。课用更结构化、更有节奏的方式，让读者完成第一次上手。它不是把书再念一遍，而是把书的核心结构拆成可练习的步骤：遇到什么问题，先用哪张表诊断；要换题，先用哪三个问题重写；要做试验，怎样设定最小的动作；要复盘，怎样读失败的反馈。

就像学做菜，看懂菜谱和第一次把菜炒出来，是两件事，课的任务是陪你把第一盘炒出来。课解决“知道怎么做”，却未必解决“真的做到”，所以它通常处在产品线的中层：比书更可操作，比训练营更轻量。

## 工具箱的位置：落地，把方法变成模板

工具箱是 AI 时代最容易被低估的形态。很多人喜欢讲理念，不愿意做工具；可是日常里起作用的，往往不是理念，而是工具，它让人在关键时刻不靠情绪，而靠流程。工具箱最要紧的不是漂亮，而是能执行。它通常包含四类东西：提问模板，教你怎样生出一个新题、怎样终结一个旧题；决策卡，帮你在意义权重上换挡；试验表，帮你设计最小试验；复盘表，帮你读结构性的反馈、封装经验。

工具箱的作用是把“思想”降成“行动”。它让产品线从内容商品走向方法商品。方法商品的复制性更强，用户用一次觉得有效，就愿意持续使用。不过也要看到，工具容易被模仿，也容易被 AI 快速复刻，所以工具箱的价值，常常不在表格本身，而在它背后那套你反复试过、改过的判断。

## 训练营的位置：加速器，把会变成成

训练营不是更长的课程，而是一个节律系统，它解决的是“知行断裂”。很多人不是不会，而是不坚持；不是不懂，而是被旧的默认值拉回去；不是缺方法，而是缺节律和反馈。训练营的价值，在于把 AEI 的节律移植到用户身上，让用户在一段时间内进入“发生模式”。

一个有效的训练营通常有三段：诊断段，明确旧题库和旧默认值，建立个人的坐标；试验段，每周一个最小试验，拿真实的反馈，迭代调整；封装段，把有效的经验封装成个人的工具箱，写进默认流程。它卖的不是陪伴，而是默认值的改写。如果只能让人热血几天，那只是情绪消费；如果能让人建立新的默认流程，那才算有用。

## 咨询、软件与 API：越往后门槛越高

咨询的高价，不是因为你“很会说”，而是因为你能重写结构。组织的问题往往不是缺努力，而是缺出题权；不是缺执行力，而是缺意义权重；不是缺人才，而是缺闭环。咨询的交付物不应当是一份建议清单，而应当是一套结构的部署：题库的重写，目标和评价标准如何更新；闭环的建立，思想创新、知识转化、产业落地怎样运转；节律的设计，周、月、季怎样运行，怎样避免燃尽和空转；工具包的落地，概念表、流程卡、指标表、复盘机制。咨询如果只是“说得对”，客户听完很舒服，回去照旧，那就没有价值。需要补一句：咨询靠的是信任和案例，起步时很难，不是任何人写了一本书就有咨询可做。

软件的意义，是把“人力交付”变成“系统交付”。工具箱成熟后，很多动作可以固化：诊断问卷、决策流程、试验记录、复盘归档、学习路径推荐、进度追踪。软件不必一开始就做得很大，但它是产品线进入规模经济的关键一步，一旦固化，交付的边际成本会明显下降。可以把软件理解为思想的产线：工业时代的产线把发明变成现金流，软件把方法变成规模交付。同时要知道，软件要花钱、要维护，要有人懂技术，这一步里失败的项目并不少见。

API 是最靠上游的资产形态：把你的方法能力变成可调用的服务，让别人把它嵌进自己的产品和流程。它意味着两件事：你的能力被标准化成接口；你的价值进入订阅模式。从收入的角度看，订阅让产品线有了持续的现金流，而不是一次性销售。但这一步门槛最高，需要更强的封装和技术配合，也需要有人真的愿意长期调用。它是机器化的一个终点，但并不是每一条产品线都要或者都能走到这里。

## 封装四件套：产品林子的根系

七种形态看起来很多，其实依赖同一个根系：封装。封装的最低结构是四件套。概念表统一语言，免得每次解释都从头开始；模型图展示关系和闭环，让抽象变得可见；指标表定义验证的信号，让“值得”可以被观察；工具箱把方法变成行动，让用户做得到。

可以把四件套理解为思想的“源代码”。有了源代码，就能编译成不同的产品形态：书是叙事版本，课是教学版本，训练营是节律版本，咨询是组织版本，软件和 API 是系统版本。没有源代码，你只能不断写文章、不断重复讲，人力迟早耗尽；有了源代码，重复的是结构，而不是你的人力。

## 最低可行产品线：从“一本思想”到“三件套”

读者很容易被七种形态吓住：我哪有能力做这么多？不需要。你只需要一条最低可行的产品线，让机器先转起来。推荐的三件套是：书或长文章，建立坐标和公共语言，作为入口；工具箱，把方法变成模板，作为落地；训练营或小班实践，用节律和反馈验证并写入默认值，作为验证。

这三件已经足够形成闭环：有入口吸引人，有工具让人能做，有小班让人发生改变。发生了改变，才可能有复购和传播，产品线才可能长出枝叶。三件套跑通了，再做课、咨询、软件、API，就不会空转。跑不通也是一种结果：它告诉你这个方向的需求不够，或者你的方法还不成熟，这时回头改题库，比硬往后加形态更有用。

## 90 天起步计划：一次练习，不是收入预期

为了让读者能动手，我把“从零到最小产品线”写成一个 90 天的节律。先说清楚它的性质：这是一份练习，用来走一遍从想法到小班验证的闭环，它不是收入预期。走完这 90 天，你可能收获一份坐标文章、一套工具箱和一轮小班的反馈，也完全可能一分钱没赚到，甚至发现这个方向根本没人要，这同样是有价值的信息。

第 1—2 周，确定一个核心矛盾和一个核心人群。你要解决的不是世界问题，而是一类反复出现的题库问题；选一个你最熟悉、最痛、最愿意长期投入的方向。第 3—4 周，写出坐标，一篇长文章或一本小书的雏形，把新问题、新坐标、新标准写清楚，不追求华丽，追求能执行。第 5—6 周，做出工具箱的第一版，包括提问模板、决策卡、试验表、复盘表，它必须能指导行动，而不是堆概念。第 7—8 周，开一轮最小规模的小班，目的不是赚钱，而是验证工具是否有效、节律是否可持续、用户怎么反馈，每周一个最小试验，每次都复盘。第 9—10 周，按反馈迭代，做出工具箱第二版和一份课程提纲，把有效的经验封装起来，把无效的删掉，形成你自己的默认流程。第 11—12 周，整理成可复制的交付包，包括文章或书、工具箱、小班流程和案例库。

这 90 天的核心不是辛苦，而是闭环。闭环一旦形成，你面对的就不再是一次爆发的赌局，而是持续迭代的过程。收入会不会随之出现，什么时候出现，本书不能替你保证；能保证的只有一件事：你从“焦虑地生产”，走到了“带着反馈地生产”。
