Skill 不是摘要，而是知识发生程序

程序化的不是全部思想，而是可以明确承担的工作关系。

◆一、两份同样简短的文字，为什么作用不同

一份摘要写道：“本文认为，知识在社会互动中持续形成，出版不应被理解为生产终点。”另一份 Skill 写道：“当用户提出应用问题时，先确定任务与来源版本，区分原文主张和新增推断，检查情境差异，再决定是否形成候选修订。”两份文字都不长，却承担不同工作。

摘要帮助读者知道论文说了什么。Skill 则试图组织系统接下来怎样做。摘要可以成为 Skill 的材料，Skill 也可以附有摘要，但二者不能互相替代。

区别不在于有没有命令句。把摘要前面加上“你必须相信”，并没有形成可靠能力。真正的 Skill 需要任务入口、判断分支、来源关系、停止条件与结果身份，使系统能够在不同输入面前采取相称行动。

因此，知识发生程序并不是把文章改写成更强硬的语气，而是把知识能够怎样进入新的现实组织出来。程序的核心不是服从，而是有根据的工作结构。

这一点决定了发生型出版的新编辑任务：审读一份 Skill 时，不只看它是否忠于原文主题，还要看它是否忠于原文的边界，是否使新增操作获得清楚理由。

◆二、“程序”是一种功能性称呼

本书把 Skill 称为知识发生程序，并不意味着它与传统确定性程序完全相同。自然语言规则交给模型执行，可能存在理解差异、遗漏和不稳定。相同输入在不同运行条件下，也可能产生不同表述或不同路径。

因此，不能把论文转 Skill 说成已经实现语义无损的严格编译。转换需要解释，解释可能出错，运行也需要测试。编译这个比喻的价值，在于强调从表达结构到工作结构的转换，而不是保证转换自动正确。

某些部分可以交给确定性程序，例如检查字段是否缺失、计算数值、验证文件格式或记录版本。某些部分则需要模型进行概念辨认和论证比较。还有些关键决定必须由人承担，例如接受一项新的理论主张进入正式作品。

成熟的 Skill 会区分这些工作，而不是要求模型凭自然语言完成所有事情。可以严格验证的部分尽量严格验证，需要开放判断的部分保留根据与责任，不能自动完成的部分明确停止。

所以，程序化并非把知识变成机械动作，而是把不同类型的动作与判断放在合适位置。它增加组织，不取消思想。

◆三、知识结果怎样转成工作条件

论文中的一个结论，进入 Skill 以后至少需要回答三个问题：它适用于什么任务，依赖什么条件，怎样判断当前任务是否满足这些条件。没有这些关系，结论只能被反复引用，难以可靠地使用。

例如，“应当区分任务完成与能力形成”作为论文命题，可以通过论证说明其必要性。进入 Skill 以后，则需要具体工作规则：用户要求评价学习时，先确定评价对象；若只有成品证据，不得直接推断长期能力；若要进一步判断，应说明需要哪些相称材料。

这里发生了一次从陈述到操作条件的转换。转换可能增加原文没有逐条写出的步骤，因此需要标明哪些是实现性设计。不能因为步骤合理，就把它伪装成作者逐字规定。

同样，论文中的限制不应被转化时省略。某条方法只讨论一种材料，Skill 就应在新材料进入时触发适用性检查，而不是把限制放在很少被调用的附录里。

知识结果成为工作条件，才使它具有可持续调用的可能。但这种可能始终依赖准确转换与后续检查，而不是来自文本形式的自动魔法。

◆四、角色扮演为什么不能代替知识规则

“你现在是一位著名作者，请用他的理论回答问题。”这样的指令可能让模型生成熟悉语气，却不能保证它准确区分原著、后人解释与自己的新推断。风格相似甚至可能提高误归属的风险。

知识发生 Skill 应当优先规定根据与边界，而不是人物性格。它可以说明当前服务围绕某位作者的作品组织，但不应假装模型就是作者本人，更不能把作者没有说过的话自动加到其名下。

用户询问新问题时，系统可以给出“依据本书框架提出的应用分析”，而不必说“作者认为”。若需要表达作者已确认的观点，应当指向正式来源；若是设计者加入的规则，也应当保留设计身份。

这并不妨碍语言具有风格。通俗、严谨、简明或详细都可以作为表达要求。但风格应当服务理解，不能成为替代证据的权威外观。

因此，Skill 的可信性来自它怎样处理知识，而不是它听起来像谁。发生型出版应当让作品获得能力，而不是让系统借作品人格越界。

◆五、一个好的入口首先辨认任务

同一句“帮我看看这篇论文”，可能意味着摘要、审稿、应用、反驳或改写。若系统没有辨认任务，就可能在用户只想理解时过度批评，在用户要求验证时只做解释，在用户准备应用时忽略条件。

Skill 可以先利用已经提供的信息确定任务，不必每次都反问。用户明确要求比较两个概念，就直接进入比较；用户要求把方法用于新的材料，才需要检查输入与范围；用户要求发表新结论，则需要更严格地处理证据与责任。

任务不清楚时，系统可以提出一个最有用的澄清，也可以在低风险情况下采用明确说明的有限假设。关键不是问题问得越多越好，而是避免重要歧义悄悄决定输出。

任务还可能在对话中改变。最初只是阅读，后来进入应用，再后来提出修订。Skill 应当识别这种转换，并相应改变所需材料与结果身份，而不是把整段对话当作同一种工作。

入口设计因此是知识规则的一部分。它决定哪些关系会被带入，哪些判断可以开始，以及系统什么时候需要停下来重新确定任务。

◆六、判断分支比固定步骤更接近真实应用

固定步骤适合条件明确的任务，但许多知识应用需要分支。材料充分与不足，情境相同与不同，反例有效与无关，都不应得到同一条处理路线。

例如，用户提交失败案例，Skill 可以先判断它是否针对原主张的承诺范围。若范围不符，说明迁移限制；若范围相符但实施不清楚，先核对过程；若实施与材料都足够，再进入理论边界分析。每个分支都有不同依据。

分支不是为了让流程显得复杂，而是保留真实差异。没有分支，系统容易用一套万能话术处理所有问题；分支过多，又可能使运行难以维持。因此，应该优先设置那些会实质改变结论或行动的区别。

分支还应当有可观察触发条件。不能写“当情况复杂时进行深入思考”这种无法检查的规则，而应说明复杂体现在哪里，例如概念不一致、关键资料缺失或来源之间存在实质冲突。

一个成熟 Skill 的价值，往往不在于顺利路径多么漂亮，而在于它为不顺利的路径准备了怎样的判断结构。

◆七、输出格式应当保存认识身份

格式不只是美观问题。若所有结果都被写成连续肯定陈述，原文、推断和假说就容易混在一起。适当的输出结构可以帮助使用者理解自己得到什么。

阅读输出可以包含核心解释与来源位置；应用输出可以包含任务理解、条件比较、方案和检查方式；挑战输出可以包含被挑战主张、反例关系、当前判断与未决问题。格式应当随任务变化，而不是强迫所有回答套同一张表。

尤其需要保留未知。字段可以写“原文未说明”“本次未执行”“证据不足”，而不是为了完成格式让模型补齐内容。结构化输出的危险之一，就是空格让系统产生填满的冲动。

因此，Skill 应当把空缺视为合法状态。一个没有答案但说明了缺口的字段，比一个貌似完整的虚构值更有价值。格式服务于可检查性，不服务于完整外观。

当输出保存身份，后续回写才能正确处理。否则，系统收到一段混合文本，很难知道哪些可以进入个人笔记，哪些需要验证，哪些已经具有正式依据。

◆八、规则之间也会发生冲突

一份 Skill 可能同时要求简洁、完整、快速、充分验证和少问问题。这些目标在某些任务中不能全部达到。若不规定优先关系，模型可能随意取舍，用户却看不见取舍发生在哪里。

知识责任相关的要求应当优先于表达便利。不能为了简短省略会改变结论的条件，不能为了快速把未执行说成执行，不能为了减少提问而猜测关键事实。其他方面可以根据任务调整。

原文忠实与新应用也可能发生张力。系统既要尊重作者，又要面对原文没有讨论的情境。合适的解决方式不是禁止扩展，而是清楚区分忠实解释与新增方案，让扩展以自己的身份接受检查。

不同 Skill 组合时，冲突可能更多。一个 Skill 要求优先考虑某种目标，另一个采用不同标准。协调者不能只挑语气最强的规则，而应当说明当前任务如何处理这些差异，必要时保留并列方案或停止组合。

因此，Skill 不是孤立指令的堆积。它需要一套能够解释冲突的秩序，尤其要使知识边界与权限边界不被其他便利目标覆盖。

◆九、程序可以引导发生，但不能命令新知识诞生

“每次运行必须提出三个原创观点”看起来很有创造力，实际上可能鼓励系统制造没有根据的新句子。新知识不是按数量要求就能保证产出的商品。

Skill 能够组织新知识更有机会发生的条件：引入不同材料，比较隐含前提，设计反例，检查情境变化，保留失败路径。但这些操作的结果可能是新命题，也可能是确认旧结论、缩小范围或发现仍然不知道。

因此，发生规则应当规定过程要求与质量门槛，而不是强制新颖结果。可以要求认真寻找差异，不能要求每次差异都推翻理论；可以要求提出候选解释，不能要求每个解释都成为知识贡献。

这使创造力与诚实不再对立。真正有价值的系统能够提出大胆假设，同时清楚说明其身份和检验路径。它不需要把猜想写成结论才能显得有创造性。

出版发生学应当避免把“持续发生”变成持续产量考核。知识有时候需要沉默、等待和不增加。能够接受这些结果的程序，才更接近真实研究。

◆十、Skill 本身也可能形成知识资产

一份经过来源核查、任务测试和长期维护的 Skill，可能具有独立价值。它保存的不只是原论文内容，还包括使内容能够进入特定工作的组织经验、边界判断和失败处理。

但价值来源需要说清楚。哪些规则来自公共论文，哪些由设计者新增，哪些案例经过使用者贡献，哪些工具由其他团队提供，都不能被一个 Skill 文件的署名全部覆盖。

Skill 的资产性可以表现为可复用能力、维护服务或特定领域的知识组织。它不自动意味着设计者对原理论、所有后续输出或使用者数据拥有排他控制。知识资产越复杂，贡献与授权边界越需要明确。

同时，Skill 需要可迁移性。若它只能在一个不透明界面中运行，用户难以理解规则，也难以带走自己的积累。适当公开规范、提供可携带记录和说明运行依赖，可以使资产价值来自能力而不只是锁定。

因此，Skill 作为新出版物形态，不仅改变技术接口，也提出新的编辑、授权和维护任务。它可以成为资产，但不能靠抹平来源与参与者来成为资产。

◆十一、可组合不等于可以随意相加

两份 Skill 各自可靠，组合以后也可能失败。它们可能使用不同概念、不同输入格式、不同证据标准，或者对同一任务提出不兼容要求。组合需要额外判断。

例如，一份 Skill 用于概念澄清，另一份用于效果评价。前者产生的解释性区分，不能未经操作化就成为后者的测量指标。两者之间需要明确转换，而不是把输出字段直接接到输入字段。

组合还需要保留来源。最终结果不能只标记“由多个智能体共同生成”，而应说明关键结论分别依赖什么，以及新增整合由谁或哪个流程提出。否则，协作会稀释责任。

为了控制复杂度，可以先组合少数任务边界清楚的 Skill，再通过测试扩展。不是连接越多越先进。某些任务由一个清楚的 Skill 完成，可能比多智能体反复讨论更可靠、更容易核查。

因此，Skill 的模块化价值来自可说明的接口与关系，不来自数量叠加。发生学的交通需要秩序，不能只赞美相遇。

◆十二、Skill 怎样接受编辑

编辑 Skill 时，不能只做语言润色。需要检查来源忠实、规则可执行性、分支完整性、权限边界、输出身份以及失败处理。文字漂亮但无法测试的规则，仍然是不成熟规则。

例如，“深入理解原文”应当改成能够检查的要求：定位核心主张、说明限定、区分原文与新增解释。“尊重事实”则需要落实为不得编造来源、缺失信息如何处理、不同证据状态怎样标记。

编辑还应检查规则是否过度。若一个简单释义任务被要求完成复杂的 SDE 审查，用户可能付出不必要成本。适当的分层调用，使严格性集中在真正需要的任务上。

审读结果可以形成变更记录。为什么删除一条规则，为什么增加停止条件，哪项测试暴露了问题，都应当有简明说明。这样，Skill 版本变化不只是新的文件日期，而具有可追踪理由。

这项工作使编辑成为知识发生的组织者，但不是要求编辑独自掌握全部专业内容。领域判断、技术测试和使用者反馈可以分工，编辑负责使它们在同一对象上形成清楚关系。

◆十三、Skill 为什么必须保留被推翻的可能

一份 Skill 可能长期有效，也可能在新任务中暴露错误。若系统把规则视为永远正确，只把失败归因于用户或模型，它就失去自我修订能力。

Skill 应当有自己的反例入口。用户可以指出规则不忠于原文，测试可以显示分支遗漏，运行记录可以揭示某项限制产生了不必要拒绝。不同问题应当进入不同修订流程。

但修改也不能完全依赖单次不满意。需要检查问题是否可重现、是否源于材料不足、是否与原任务范围有关，以及修改会不会破坏已有可靠能力。规则开放不等于规则任意。

正式更新以后，应当重跑相关测试，并保留旧版本供必要核查。某条规则被删除，不意味着过去依它产生的结果可以被无声抹去。发生史仍然需要保存。

因此，Skill 不仅组织知识发生，也参与自身发生。它既是程序，也是需要被审读、测试与修订的知识对象。

◆十四、从一份说明书到一个可承担的能力单元

到这里，我们可以给出更完整的定义：SDE 知识发生 Skill，是围绕特定知识来源与任务范围，组织显露、差异序列和特征纠缠分析，并规定应用、验证、结果身份与回写边界的可调用能力材料。

这个定义没有把 Skill 神化成独立智能。它需要模型、工具、资料和责任安排才能运行，也需要实际测试才能支持相应能力声明。定义的作用是明确应当检查什么，而不是宣布可靠性已经获得。

摘要告诉我们一项知识说过什么，Skill 帮助组织它接下来怎样工作。原文提供论证密度，Skill 提供任务结构，运行提供具体结果，验证与治理决定哪些结果能够形成后续知识。四者共同构成发生型出版的基本关系。

下一章将把这种关系进一步展开为结构规范。规范不是为了让所有知识长得一样，而是为了让不同知识单元在保留差异的同时，能够被理解、审读、调用和合作。

出版物的新物种，不是一个会说话的文件，而是一项有来源、有边界、可以继续工作并接受修订的知识能力。

带走的话

程序化的不是全部思想，而是可以明确承担的工作关系。

把知识组织成 Skill，需要有选择的压缩，也需要回到更丰富原文的通道。规则使任务可以进入，反例与停止条件则使规则不至于封闭。真正的知识发生程序，应当既能指导使用，也能接受对自身规则的挑战。

继续发生的一问

删去一项 Skill 限制会让任务更快：你怎样判断那是优化，还是删掉了关键根据？
