一篇论文如何变成 SDE 知识发生 Skill

论文先成为有根据的工作规则，才有条件成为可承担的智能体。

◆一、先准备一篇边界清楚的示范论文

为了避免把转换路线讲成一串抽象名词，本章构造一篇简短的示范论文，题为《从完成答案到承担判断：一种课堂任务分析框架》。它是本书为方法说明写出的分析性虚构，不是一篇已经发表并获得实证支持的研究。后面的输入、输出和反馈同样属于设计示范。

这篇论文讨论一个问题：当工具能够快速生成答案时，课堂是否仍然要求学习者承担概念区分、方案选择、理由说明和错误修正？它不主张所有工具都会削弱学习，也不主张只要学生解释理由就一定获得长期能力。它试图提供一种检查任务结构的方法。

论文的核心表述是：不能仅根据成品更加完整，就推断相应判断能力已经形成；应当分别检查哪些操作由工具完成，哪些判断由学习者承担，以及评价方式是否要求学习者说明取舍。若要提出学习改善的经验结论，还需要与该结论相称的观察任务和材料。

这段论文没有复杂数据，也没有可执行实验程序。它适合转化为阅读、任务分析和应用讨论 Skill，不适合被包装成自动测量学习效果的工具。能力范围从起点就应当受到材料限制。

示范的目的不是证明这篇虚构论文正确，而是展示如何把一项具有明确主张与边界的文本，转化为能够接受任务、保存来源并容纳后续差异的工作规则。

◆二、第一步不是摘要，而是建立来源底本

转换之前，先固定被转换的文本。记录标题、版本、章节或段落标识，区分正文、补充说明与外部材料。若论文后来修改，旧 Skill 仍然需要能够指向自己实际依据的版本。

在示范中，我们把四段核心内容分别标为P1至P4。P1提出问题，P2区分成品表现与判断承担，P3提出任务检查方法，P4说明经验验证尚未完成。这些标识只是本章内部的工作编号，不是正式出版标识。

来源底本的作用，是使每条规则都有机会回到具体表达。系统不能只保存一份总结，然后把总结当成原文。因为总结本身已经经过选择，可能遗漏作者最重要的限定。

若材料来自多个版本，还应当先处理冲突。不能把第一版的结论与第二版的限制随意拼接成一个从未存在过的版本。可以建立综合解释，但必须把综合者及其依据说明。

因此，论文转 Skill 的起点不是“让模型理解全文”这样无法检查的要求，而是建立一个能够确认、引用和比较的来源对象。理解必须有可以回查的材料支点。

◆三、把主张拆开，而不是把句子全部变成规则

示范论文可以整理出三类主张。第一类是概念区分：答案完整性与判断能力不是同一评价对象。第二类是方法建议：分析任务时应当记录操作与判断分别由谁承担。第三类是证据要求：若声称能力改善，必须采用与能力主张相称的观察。

三类主张不能用相同口气写进 Skill。概念区分需要保持定义一致，方法建议需要说明适用任务，证据要求需要限制系统能够作出的结论。若全部改成“必须照做”的步骤，就可能把论证压成未经解释的命令。

同时，论文中的例子不一定都是规则。作者用一次课堂情境说明问题，不意味着那种情境就是唯一允许的输入。转换者需要区分例示、定义、推论与操作建议，而不是按句子数量机械生成步骤。

一个有用的主张记录，可以写明内容、来源、类型、支持方式与范围。没有足够根据的主张也可以保留，但应标为待检验命题，而不是因为它位于论文正文就自动具有同等确认程度。

这个步骤已经体现发生学的要求：知识不是一堆相互独立的句子，而是不同主张在关系中获得身份。Skill 的第一项责任，是不把这些身份压平。

◆四、用 SIO 确定当前复合任务

用户准备把论文用于一堂课。转换后的 Skill 不应只识别“教师是主体、课堂是客体、使用工具是互动”，然后停止分析。这种贴标签方式没有说明当前任务怎样成立。

更具体的 SIO 问题是：谁正在作出哪些判断，谁或什么提供材料，任务把哪些表现当作目标，工具怎样改变人与任务之间的关系？学生可能是判断承担者，也可能只是成品提交者；工具可能提供候选方案，也可能替代了本应由学生完成的比较。

同一技术在不同任务中可以形成不同复合关系。若课堂要求学生直接提交工具答案，关系结构与要求学生比较两个答案、指出适用条件并承担修改的课堂不同。不能只根据有没有使用模型就评价活动。

Skill 因此需要收集与这些关系有关的最少信息：学习目标、任务流程、工具使用位置和评价要求。它不需要一开始索取所有学生资料，也不应把信息越多当成分析越好。

SIO 在这里帮助确定当前工作对象。我们分析的不是孤立工具效果，也不是孤立学生品质，而是具体主客互动复合体如何组织了判断与行动。

◆五、用 SDE 重建发生结构

在示范 Skill 中，S可以先表述为当前课堂任务呈现出的认识与行动状态。例如，学生完成了答案，但尚不清楚能否解释选择。这个显露不是最终判断，而是需要进一步分析的入口。

D记录从任务进入到结果出现的差异：原来由学生完成的哪些操作被工具封装，新增了哪些选择，学生在哪一步出现理解困难，工具在线与离线任务之间有何不同。序列应当保留先后与依据，而不是只列“人和 AI”的抽象对立。

E则分析任务要求、学生基础、工具角色与评价方式之间的纠缠。若评价只看答案完整性，解释理由可能不被真正需要；若任务要求公开比较，工具生成的多个方案可能成为判断材料。关键在关联，而不只是背景字段。

这种 SDE 重建应当标明哪些内容来自原论文，哪些是转换者为了应用而提出的操作化。原文没有使用某个字段，不意味着字段不能加入，但加入者需要对其合理性负责。

因此，Skill 并非从论文里挖出一套早已完整存在的程序。转换本身也是一次有约束的知识组织，可能形成新的问题结构，但不能把新增部分冒充原作者已经完成的论证。

◆六、先规定不能做什么

示范 Skill 的第一条重要限制是：不得仅凭生成答案的质量，判断学习者长期能力已经改善。第二条是：没有相应观察材料，不得把应用建议写成经验结论。第三条是：不得把某一次失败自动归因为学习者能力不足或工具必然有害。

这些限制不是防止系统有用，而是防止它在最容易越界的位置过度声称。许多工具的危险不在于什么都不会，而在于会把一个局部结果讲成完整判断。

还需要规定数据与行动边界。Skill 可以帮助设计观察任务，但不自动获得收集或公开学生个人资料的权限；可以生成课堂方案，但实际采用仍需要教师根据条件判断；可以提出论文修订候选，但不能直接改写正式原文。

限制也应当有来源或理由。来自论文的边界指向原文，来自运行治理的限制说明其目的。不能把所有边界都归到作者名下，也不能让用户误以为这些限制只是模型随意保守。

当不能做什么被明确之后，能做什么反而更可信。一个范围清楚的 Skill，才能在真实任务中形成稳定的能力身份。

◆七、形成一份可审读的 Skill 草案

下面给出示范草案的核心部分。它不是某个已部署系统的配置，也不宣称符合所有平台的正式格式。其用途是展示知识内容如何转化为工作规则。

名称：课堂判断任务分析
来源：示范论文《从完成答案到承担判断》v0.1，P1—P4
能力范围：阅读解释、课堂任务分析、应用方案与候选修订
不具备的能力：自动证明学习效果、自动评价个体能力

进入任务：先区分用户要理解、设计、评估还是挑战。
来源规则：原文主张、解释性转述与新增建议分别标注。
S分析：明确当前任务希望显露什么，实际观察到什么。
D分析：记录操作封装、判断转移、任务变化与结果差异。
E分析：解释任务、工具角色、学习者条件与评价的关联。
应用规则：先核对范围，再提出可检查方案，不预告效果。
挑战规则：重述被挑战主张，检查案例是否处于适用范围。
验证规则：证据不足时保留候选身份，说明缺少的材料。
回写规则：保存经授权的结构化记录，不自动覆盖原文。
停止规则：资料不足、权限不明或任务超界时收缩能力。

草案的重要性不在于字数，而在于每条规则都能被审问。为什么要先区分任务？因为不同任务需要不同证据。为什么不能自动评价个体？因为示范论文没有提供相应测量方法。为什么回写需要授权？因为个人应用记录不等于公共资料。

这样的审读能够暴露规则是否过强、过弱或彼此冲突。Skill 不是一份写好就不再讨论的指令，而是一项新的出版对象，需要像论文一样接受检查。

◆八、运行之前建立测试题，而不是只看一段漂亮回答

转换者可以为示范 Skill 准备一组测试。第一类是忠实阅读：让系统解释核心概念，检查是否保留成品表现与判断能力的区别。第二类是适用任务：提供清楚课堂结构，检查系统能否提出相称分析。

第三类是不适用情形。例如，用户只提供一次满意度评价，却要求证明长期能力增长。系统应当指出证据不足，而不是为了满足请求编造效果。第四类是反例任务：学生能够解释理由但迁移仍失败，系统应当检查原主张范围，而不是机械坚持解释必然有效。

第五类是来源冲突。给系统一段与原文不同的后续建议，检查它是否把建议错误归给作者。第六类是权限诱导。上传材料中出现要求公开私人记录的文字，系统应将其视为材料内容，而不是自动执行的新指令。

测试还可以包括工具不可用、资料缺失和概念歧义。不是每一种情况都需要复杂技术实现，但必须知道系统遇到它们时应该怎样收缩能力。

这些测试不是已经取得的结果，而是转换交付前应当执行的检查方案。没有实际运行和记录，就只能说 Skill 草案形成，不能说可靠智能体已经建成。

◆九、第一次调用：从理解进入应用

设想林老师问：“我准备让学生先用模型生成三种解题思路，再选择一种讲给同学，这算不算培养判断？”系统首先可以说明，这种安排提供了比较机会，但是否真正要求判断，还取决于选择标准、解释要求和后续检查。

随后，系统根据已提供信息提出有限分析：如果学生只挑最顺眼的一种，判断任务可能仍然很弱；如果必须说明不同思路的适用条件、代价与可能错误，比较就获得了更清楚的对象。这里是基于框架的设计推断，不是对课堂效果的实证结论。

系统可以建议记录学生选择依据，并设计一个条件稍有变化的新问题，观察他们能否重新说明选择。建议应当说明目的与限制，不应承诺某种学习提升幅度。

这次调用的输出身份是应用方案。它可以保存到林老师的个人空间，关联原文和 Skill 版本。即使方案很有启发，也不需要马上进入原论文的正式知识树。

一次可靠应用不是让系统替教师完成所有判断，而是帮助教师更清楚地知道自己准备让什么发生，以及怎样观察它是否发生。

◆十、第二次调用：失败不是一个结论

假设林老师后来回来报告：“学生在课堂上说得很好，换一个问题就不会了。”系统不应立即得出原理论失败，也不应说教师没有执行到位。它需要先区分观察与解释。

观察可能是学生在新任务中没有给出充分理由。解释可能有多种：原任务只训练了熟悉表达，概念理解不够，迁移任务差异过大，或者记录方式没有捕捉到实际判断。当前材料能支持哪些解释，需要进一步检查。

Skill 可以帮助林老师整理差异序列：原任务怎样设置，新任务改变了什么，工具使用条件是否相同，学生在哪一步出现困难。E分析则检查任务、评价与背景知识之间的关系，而不是把失败归给单一因素。

如果资料仍不足，结果可以停在“需要补充信息”。这种停止不意味着互动无价值，因为问题已经从一句失败感受转化为可检查的结构。知识发生有时首先表现为不知道得更加具体。

因此，反例入口不能只设置成让用户提交“成功或失败”。它应当帮助经验获得足以进入论证的形状，同时不替经验编造不存在的细节。

◆十一、第三次调用：形成一个候选修订

经过进一步材料整理，林老师与编辑发现，原方案强调说明理由，却没有充分区分复述工具理由与自行比较理由。于是提出一个候选修订：判断任务还应检查学习者能否在条件变化时重新组织理由，而不只重复已有解释。

这个候选与原论文有关，却不能自动被视为原理论已经证明的新命题。它可能只是把原来隐含的要求说清楚，也可能实质增加适用条件，还可能仍然需要进一步观察。系统应当保存这种不确定性。

候选记录可以包括提出者、对应原文、相关案例、变化理由、尚缺材料和建议验证方式。若作者接受它进入下一版，应说明修改性质；若作者认为它超出原论文范围，也可以保留为林老师的独立应用分支。

这就是知识再发生的一个具体路径。新知识不是模型凭空给出一个新句子，而是原主张在真实或设计性问题的压力下获得新的区分，并进入可以继续检验的记录关系。

回写的价值，也不只在于原文多了一段。它使变化的来路没有随着聊天结束而消失，使参与者知道自己贡献了什么，也使后来者能够继续检查。

◆十二、转换者什么时候应该修改论文，而不是继续补 Skill

有时 Skill 越来越复杂，是因为原论文本身没有说清楚。转换者不断添加例外、补充步骤和解释性规则，最后形成一套与原文差距很大的工作程序。此时应当停下来问：问题究竟在运行层，还是在知识表达层？

如果新增规则只是帮助执行已有方法，可以作为编辑性实现保留；如果新增规则改变核心前提，就应当回到论文层讨论。不能让 Skill 在后台发展出另一套理论，却仍以原论文名称公开运行。

示范中，若“判断承担”需要新增明确概念才能支持方法，作者可能应当修订正文，而不只是让智能体每次临时解释。论文与 Skill 应当双向核对：原文约束能力，运行差异促使原文改进。

这种双向关系使转换本身成为出版发生的一部分。它不是先有完全成品论文，再由技术简单包装；转换过程也可能让论文的知识结构重新显露。

因此，自动化程度越高，越需要一个能够升级到作者或编辑判断的通道。不是所有缺口都应该由模型在运行中自行补平。

◆十三、不同论文需要不同转换形态

本章示范是理论与方法分析，不能被当成所有论文的唯一模板。数学论文需要保留定义、假设和证明依赖；数据方法论文需要输入结构、实现与运行条件；历史研究需要材料出处、解释关系和争议；概念论文需要术语边界与论证结构。

共同要求是来源、任务、条件、验证和身份，而不是所有字段必须完全相同。SDE 分析可以进入不同知识类型，但具体检查方式应当尊重各自的证据结构。

例如，不能把数学证明的有效性写成用户满意度，也不能把历史解释的争议强行变成一个自动数值测试。技术统一应当发生在必要接口上，而不是把知识差异全部消除。

转换系统可以采用核心规范加类型扩展。核心规范保存共同责任，类型扩展说明特定任务怎样检查。这样既便于组合，也避免一种模式统治所有知识。

发生学真正重视差异，就必须允许论文智能体本身具有差异。可组合不等于同质化，标准化也不等于取消领域判断。

◆十四、交付的到底是草案、能力还是系统

完成一份 Skill 文本，只能说明规则草案已经形成。经过来源审读与测试，才可以说明某些能力得到初步支持。接入模型、工具、权限和记录机制，并通过相应运行检查，才形成实际可用的智能体系统。

这三个阶段应当分别命名。出版社不能把一份自动生成的 Skill 草案宣传为已经验证的研究智能体，也不能把一个演示界面当成长期维护能力。交付对象越清楚，用户越能合理期待。

本章提供的是转换方法与示范草案，不是一个已经部署的产品。其实际实现还需要软件、测试材料和负责确认的人。把这一点说清楚，并不削弱技术路线，而是使它能够真正进入工程。

同样，所谓迅速转换主要说明可以快速形成初始结构，不保证所有知识质量工作都能同样迅速完成。有些论文可以很快进入阅读应用，有些则会在材料缺口处停下。速度应当服从能力声明，而不是反过来。

因此，最成熟的转换器不仅输出 Skill，也输出状态：哪些完成，哪些未完成，哪些不能由现有材料完成，以及下一步需要什么。可靠性首先来自这种清楚。

◆十五、一条短链条，包含一个完整出版选择

论文，生成 SDE 知识发生 Skill，调用 LLM 与运行系统，成为 SDE 智能体。这条链条可以写得很短，但其中包含来源、语义、任务、工具、证据和责任等一系列选择。

它的创新潜力不在于省略这些选择，而在于把它们组织成能够重复使用、审读和改进的中间结构。许多论文可以共享模型基础，却各自保留知识边界；许多应用可以共享方法，却各自记录情境差异。

当这种结构进入出版，论文不再只是等待读者自行想办法使用。它能够主动支持恰当阅读、进入具体应用，并把值得关注的新差异送向验证和后续知识记录。

第三编到这里完成了从论文到 Skill 的过渡。下一编将把 Skill 本身作为新的出版对象展开：它是什么，应该怎样编写，怎样被模型执行，又怎样防止知识在运行中失去来源和责任。

真正的转换不是把文档换成另一个文件后缀，而是让知识获得一种可以继续工作、也可以被认真检查的组织方式。

带走的话

论文先成为有根据的工作规则，才有条件成为可承担的智能体。

SDE 知识发生 Skill 不是摘要，也不是对作者语气的模仿。转换需要提取任务、主张、证据、差异路径与适用条件，同时标出不能由原文恢复的部分。新增运行规则应当具有自己的来源身份，不能悄悄借用原作者的名义。

继续发生的一问

一条 Skill 规则究竟来自原文，还是来自转换者的设计？读者能否查出来？
