通义千问 基底 · 浏览器直连测试

测试"阿里通义千问 Qwen"能否像 DeepSeek / GLM / Kimi 那样,从网页前端直接调用(CORS 是否放行)。SDE Universes 内部工具。
⚠️ 千问有两个地域,Key 不通用:阿里百炼分"北京站"和"新加坡站",两个站的 API Key 是不同的——你在哪个站开通、拿的哪个 Key,就只能调那个站。本页两个站都测,你能一眼看出你的 Key 属于哪个站、哪个站能前端直连。

关于 Key 安全:纯前端运行,Key 只在你自己浏览器里用于发一次极短测试请求(约几十 token),不上传本站服务器、不写日志、不落库。建议用额度有限的测试 Key,测完可在阿里后台删除。

说明:测试意味着什么

为什么测两个域名? 千问(阿里百炼)分两个地域,dashscope.aliyuncs.com(北京站)和 dashscope-intl.aliyuncs.com(新加坡站),两者 Key 不通用、CORS 策略也可能不同。你的 Key 属于哪个站、哪个站能前端直连,都要测出来。

三种可能结果:
• 通过 —— 该域名放行了 CORS,浏览器能直连,可以像 DeepSeek/GLM/Kimi 一样接入发生器。
• 被 CORS 拦 —— 请求发出去了,但浏览器因跨域策略拦下响应,无法前端直连,需走后端代理。
• Key/其它错误 —— 能连通但 Key 无效(可能是另一个站的 Key)、模型名错、或额度不足(此时 CORS 其实放行,换对参数即可)。

如何区分"CORS 拦"和"其它错误"? 若浏览器控制台(F12)报 CORS policy / Failed to fetch 且本页显示"网络层失败",基本是 CORS 拦;若返回了 JSON 错误(如 401/400/404),说明 CORS 放行了,只是参数问题(最常见是 Key 属于另一个站)。
