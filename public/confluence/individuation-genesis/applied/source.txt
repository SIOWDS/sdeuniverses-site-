TITLE: 先回答“你在认哪一个”，再设计身份系统
SUB: 一套把对象、关系、差别、名称与版本连续分开记录的实践流程
ABS: 身份系统常把同名当同一、把同号当同一，或把记录变化误当对象变化。本文提供十四步方法：先确定对象层级，再画关系、差别与指称锚，处理改名、拆分、合并和修复，配套误并误拆读数、申诉通道与停止条件。

== 这套方法做什么、不做什么
这套方法用于数据治理、档案、项目管理、组织交接、产品账号和人工智能实体识别中反复出现的身份难题：两条记录是否指向同一对象，一条记录变化后是否仍延续，两个对象合并后旧责任怎样追踪。它不替代身份证明、司法认定或专业领域标准，而是把容易混在一起的判断拆开，让团队知道争议究竟发生在哪一层。最小试点选一类经常误并或误拆、但不直接决定高风险权益的对象，抽取二十个已复核案例。

建立对象卡，写明对象层级、关系材料、区分条件、当前名称、允许变化和撤回入口。先复现旧系统结论，再用新卡重判，比较分歧来自材料不足、规则冲突还是名称误导。项目输出不追求一个万能身份分数，只交付身份规则、边界案例、版本记录和纠错路径。任何自动合并都保留原记录，任何拆分都保留关联历史。若团队无法说明回退办法，不启动批量处理；身份工程首先是可纠错工程。启动人还要写清谁承受误并、谁承受误拆，以及两类伤害的优先级。若收益归平台、纠错成本全给当事人，试点设计不合格。先调整责任和资源，再谈识别精度。

- 不负责决定人的本质和价值。
- 不负责把账号或算法分数当成人。
- 不负责替法律身份和权利程序作最终裁决。

== 先守住边界
个人身份、健康、账户与关系材料按最少字段收集，未取得同意不合并。对象可拒绝自动匹配、查看用于指认的材料并随时退出非必要分析；退出后，管理员删除工作副本并通知所有接收旧指称者。出现冒名、服务中断、歧视或现实权利损害，系统立即冻结自动动作并升级给人工责任人。纠错不能只改主表，还要沿传播链撤回旧名。未成年人、患者、员工等权力较弱对象有独立申诉入口，原命名者不得独自驳回。任何置信度都不能取消人工判错与紧急保护。

对象本人可看到名称来源、关系证据和下游去向，并能冻结自动合并。拒绝匹配不影响原服务，退出后删除试验字段而保留法定记录。冒名或错配一旦影响账户、待遇或声誉，先恢复人工核验，再通知所有已知接收者；算法置信度不能推迟紧急保护。

这套方法用于数据治理、档案、项目管理、组织交接、产品账号和人工智能实体识别中反复出现的身份难题：两条记录是否指向同一对象，一条记录变化后是否仍延续，两个对象合并后旧责任怎样追踪。

== 先定位：问题究竟卡在哪一环
从一宗可能认错人的记录入手，先冻结账号、编号和姓名所带来的先入判断。本节集中提出五问：正在识别的是人、账号还是一次事件？ 哪些关系让候选对象从相似物中显出？ 哪个名称把它接入共同记录？ 什么条件出现时必须判为不是同一个？ 结构变化以后谁负责撤回错误指认？

每个答案都要指向关系、时间、来源和撤回入口。相同字段只能证明相似，不能单独完成指认；字段变化也不当然意味着换了对象。若记录系统没有保留关系证据，就把本项写成不可判，而不是让算法置信度替代责任。

个体化对象卡收集对象在关系中显出的证据，差异呈现完整度检查关键差别是否被界面和流程看见。指称接住率计算名称成功连接到既有记录的事件，命名不变性违规数查同一名称被强行维持的次数；三权能一致率比较命名、判错与计算是否由可互相纠正的主体承担。

抽一张高置信对象卡交给不知原结论的复核者，让他从关系证据重新指认，并要求能指出撤回条件。两人若只因同一编号而一致，结论无效；若分歧来自关系缺失，就先补证据。定位最终须留下谁能判错、谁负责撤名以及纠错怎样通知受影响者。

== 一张不下结论的事实底稿
底稿逐次指认列对象层级、关系来源、可辨差别、名称来源、计算结果、冲突候选、撤回条件和通知去向。事实栏放申请、路线、维修、合并拆分与原始确认；推断栏才写“仍是同一个”。个体化对象卡保存关系证据，差异呈现完整度查关键差别，指称接住率只算有独立证据的连接，命名不变性违规数登记该撤名却强留的事件，三权能一致率比较命名、判错与计算责任。字段不能改变指认、冻结或通知就删去。

个体化对象卡保存关系材料，差异呈现完整度检查关系是否化成可辨差别，指称接住率再看名称有没有接对记录。命名不变性违规数专查结构变化后仍强留旧名的事件，三权能一致率则比较命名者、判错者、计算者能否互相纠正。卡片材料不足时，其他读数都应标成暂缓；三权能相同也不当然是好事，关键在是否存在撤回路径。复核者只看关系材料重做一次指认，若必须依赖系统原编号才能成功，名称没有接住对象，只接住了数据库位置。对象卡还应保存名称改变前后的通知范围，因为纠错不止是数据库改一格。

== 建立个体化对象卡
同一个业务页面可能同时出现人、账号、设备、订单、文件和项目六类对象。先为每条规则写一个主语：“本规则识别的是一次申请”“本规则延续的是项目版本”。禁止只写“用户身份”，因为同一人可以有多个账号，同一账号也可能由组织多人操作，设备变化更不能直接等于人的变化。

对象卡至少列边界、起点、终点、允许的组成变化和不得继承的属性。订单合并不自动合并付款责任，文件复制不自动复制授权，部门改名不自动抹去旧承诺。每个属性都注明属于哪一层，系统查询时先选对象层级，再返回名称和关系，避免跨层偷渡。

用三问测试定义：它能否处理同名不同物，能否处理同物改名，能否处理一物拆成两物。任一问题只能靠人工猜测，就补规则或承认未知。对象边界宁可窄而清楚，不要为了一个全局编号把不同责任强行压成同一东西。再用一条自然语言例句验证每个对象，如“这次申请在改地址后仍是同一次申请”。业务、技术和权益人员若对主语指向不同，就暂停建模，先统一对象词典与反例。

动作甲：先写正在认人、账号还是事件；动作乙：附一项关系证据和撤回条件。受理员负责，对象本人或代表复核，时限为首次动作前；禁止只抄编号，对象卡可冻结。

== 检查差异呈现完整度
为目标对象画关系表，不先画外观特征。项目可包括发起人、目标、合同、资源、版本和交付；数据文件可包括来源、生成过程、权限、内容摘要和后续派生；账号可包括创建、验证、使用、恢复和授权事件。每条关系写来源、时间、可信范围与可更改性。关系不是越多越好。选择与当前用途有关、来源相对独立且能改变判断的材料。多个字段若都复制自同一旧表，只算一个来源；同一错误经不同系统回流，不能伪装成多方印证。用来源图标出共同上游，防止“证据很多”其实只是同一录入被重复显示。每次判断至少保留一条连续关系和一条排除竞争对象的关系。前者说明为什么仍是它，后者说明为什么不是旁边那个。若只能找到支持关系、找不到排除材料，输出候选而非确定身份。关系表随真实事件更新，旧版本不可覆盖删除。对高代价决定，还要有一条不依赖主数据库的复核来源，避免数据库自身错误循环证明自己。若独立来源不可得，降低确定度并扩大人工解释，不用更多同源字段替代独立性。

动作甲：列出关键关系是否已显成可辨差别；动作乙：把缺失项标不可判。记录者执行，独立判错者复核，时限为当日；禁止用置信度补空，材料不足即停止自动认同。

== 把差别写成可核对条件
差别用于让候选从背景中浮出。把“看起来不一样”改成字段与阈值，例如时间区间不重叠、来源链不同、关键内容冲突、授权主体不同。

每项差别写它能排除什么、不能排除什么，以及技术变化会不会让它失效。姓名拼写差异通常弱，独立来源和不可同时成立的事件通常更强。差别也会被复制、伪造或自然变化。

设备号可能更新，地址可多人共用，生物特征也可能受采集条件影响。不要把任何单字段设为永久本质；为关键差别配第二来源，并设置人工复核区间。

系统应能输出“不足以区分”，不能为了完成率强制二选一。每季度抽取被合并案例中的冲突材料和被拆分案例中的连续材料，检查差别权重是否反向工作。

若某差别只在一类群体上产生大量冲突，要排查采集偏差和结构性不利，而不是给该群体加更严格证明负担。差别规则设有效期，技术、业务或社会条件变化时重新验证。曾经稀有的特征可能后来普及，曾经稳定的地址可能因灾害或迁移失效；过期条件自动降级为线索，不继续充当唯一判据。

动作甲：把“像”改写成可复查的时间、路线或来源；动作乙：给每项写反例。案件负责人执行，另一来源持有人复核，时限为一次核对；禁止使用人格判断，条件可随证据撤销。

== 计算指称接住率
指称锚是团队用来再次找到对象的入口，可以是受控编号、版本地址、登记名称或经过授权的组合键。它必须唯一到目标层级、可追踪创建者、与关系材料相连，并能在错误时撤回。随机编号通常比姓名稳定，但编号本身不证明所指正确。创建锚时记录绑定依据、时间、执行者和置信状态；调用锚时返回对象层级和当前状态，不能只吐出号码。若锚被复制到别系统，连同用途限制与版本一起传递。

外部系统无法承载限制时，不做静默同步，改为受控查询或明确的低可信映射。锚的治理包括改名不换对象、对象变化换版本、错误绑定撤销、历史查询与别名管理。禁止删除旧锚后重建同号来“清理数据”，因为这会让两个时期的责任混在一起。一个好锚减少寻找成本，却不垄断最终解释权。定期做锚碰撞测试：随机取一批号码，确认不会同时指向两个活动对象；再取已停用号码，确认系统不会误分配给新对象。发现碰撞先冻结写入，沿创建日志定位源头，不能靠覆盖其中一条记录消除报警。

动作甲：只纳入名称接到独立关系证据的案例；动作乙：抽一宗高置信错配重算。数据员负责，申诉人员复核，时限为两日；禁止以主编号自证，比率冲突即暂停。

== 记录命名不变性违规数
为每个对象设置内部稳定锚、展示名称和外部号码三个字段。展示名称可变，外部号码可能由别机构回收或改版，内部锚只在本系统对象边界内稳定。

任何匹配规则不得因为名称相同直接合并，也不得因为名称不同直接拆分；它只能触发关系复核。改名流程先验证请求权限，再记录生效时间、旧名查询期、依赖系统和通知范围。

涉及个人自我陈述时，展示与称呼应及时尊重更新；历史合规记录按适用规则最小保留，不能借“历史真实性”继续不必要暴露。对象连续与展示方式是两项不同决定。

外部号码变更时建立一对一、一对多或多对一映射，并标明有效期。若无法确定对应，保留未决，不用最近姓名填空。审计随机搜索旧名、当前名和内部锚，确认三条路径回到正确层级且不会泄露无关历史。界面应明确展示“这是名称相似候选”还是“这是已核验同一对象”，不能用相同颜色和按钮混在一起。人工选择合并前显示会继承的权限、债务和历史，让操作者看见决定后果，而非只看匹配便利。

动作甲：找结构变化后仍强留旧名的记录；动作乙：沿下游逐处撤回并通知。名称管理员负责，受影响对象复核，时限为发现后一个工作日；禁止只改主表，未通知项持续挂账。

== 角色与权限分开
执行者收集关系材料、建立对象卡和发送纠错通知，不作最终权利裁决。决策者批准匹配、拆分、合并或冻结，并写明对象层级。复核者拥有独立判错权，能查看原材料和撤回自动动作；原决策者不得独自复核自己。对象是被指认的人、账号、事件或项目，必须明确是哪一层，并拥有拒绝、退出和申诉入口。计算者只报告结构对应，不能替命名者或判错者承担责任。通知管理员沿下游撤名，直到对象确认关键接收处已更正；主表更新不等于责任链完成。 每个身份决定都要有可读理由：识别的对象层级、采用的关系、关键差别、使用的锚、规则版本和人工责任人。受影响者能够查看与自己有关的必要信息、提出更正并获得时限内回应。不能因申诉而降低服务或增加惩罚性标记。复核者不应是原决定唯一制定者。高风险案例由业务与权益角色共同看，技术人员解释模型而不替代价值判断。改判后不仅修主记录，还要寻找下游副本、缓存和报告；建立传播清单，直到残留错误被关闭。

== 读数、采集办法与代价
一宗名称、关系与对象层级发生冲突的指认先定材料边界，各项读数分别报告，不生成总分：
- 个体化对象卡｜来源：关系材料、名称与撤回链；频率：每次重要指认一次；缺失：表示对象层级未定；反向优化：堆字段制造确定感；改善上限：足以支持或拒绝一次指认即可。
- 差异呈现完整度｜来源：关键关系是否进入记录；频率：材料变化时更新；缺失：表示关系尚未显出；反向优化：增加无关字段冲高完整度；改善上限：覆盖决定性差别即可。
- 指称接住率｜来源：名称与独立关系证据；频率：一个复核周期一次；缺失：表示连接证据不足；反向优化：沿用主编号冲高比率；改善上限：用于触发抽查，不追求百分之百。
- 命名不变性违规数｜来源：结构变化、旧名与通知记录；频率：每次拆分合并后；缺失：表示撤名条件不清；反向优化：频繁改名制造违规下降；改善上限：发现一次强留旧名即可纠错。
- 三权能一致率｜来源：命名、判错、计算责任日志；频率：权限变化时；缺失：表示责任人不可追；反向优化：让同一人补签冲高一致；改善上限：只确认三权能可互相纠正。

个体化对象卡以一次指认为单位，保存关系证据、名称来源和撤回路径。

== 最容易把方法做坏的三种方式
个体化对象卡一旦脱离自己的材料，最先出现以下三种坏法：
- 坏法：堆积更多身份字段制造确定感，隐私负担上升。保护：保护措施是每字段回答改变哪项指认，答不出删除。
- 坏法：主表改名后便宣布纠错完成。保护：保护措施是沿下游通知，未撤回节点持续挂账。
- 坏法：原命名者兼任唯一申诉复核。保护：保护措施是独立判错权和对象本人可见的冻结按钮。

每个身份决定都要有可读理由：识别的对象层级、采用的关系、关键差别、使用的锚、规则版本和人工责任人。受影响者能够查看与自己有关的必要信息、提出更正并获得时限内回应。不能因申诉而降低服务或增加惩罚性标记。复核者不应是原决定唯一制定者。高风险案例由业务与权益角色共同看，技术人员解释模型而不替代价值判断。改判后不仅修主记录，还要寻找下游副本、缓存和报告；建立传播清单，直到残留错误被关闭。无法追回的披露应告知适当责任人并采取补救。版本记录保存规则变化的理由和适用范围。

== 什么时候应该停，什么时候说明理论可能不对
操作停手线：出现冒名、权利损害、自动动作无法冻结或旧指称未能通知下游时停；恢复人工处理并沿链纠错。

理论撤回线：单一内部特征或纯结构位置能稳定完成追踪、判错与责任，移走三权能任一项也不改变结果时，撤回同一性必须经指称生成的命题。

出现未经授权的数据扩张、误并导致权益受损、自动系统越过人工边界、未成年人或弱势群体承担额外证明负担、无法回退批量变更时，立即停止并恢复安全版本。涉及司法、医疗、救助等决定，转由具备权限的专业程序，不拿本方法补授权缺口。若内部单一特征在目标领域始终唯一、稳定且足以决定身份；加入关系、差别和指称锚没有减少误并误拆；三类动作不能产生可区分的失败；或对象层级化只增加成本而不改善任何边界判断，那么母文框架在该用途不成立，应改用更简单规则。试点连续两轮没有减少高代价错误，或复核成本超过预设上限，也应结项。报告保留哪些普通数据清理有效、哪些理论判断被削弱、哪些仍未知，删除无必要个人数据。
