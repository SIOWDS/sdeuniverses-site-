TITLE: 先回答“你在认哪一个”，再设计身份系统
SUB: 一套把对象、关系、差别、名称与版本连续分开记录的实践流程
ABS: 身份系统常把同名当同一、把同号当同一，或把记录变化误当对象变化。本文提供十四步方法：先确定对象层级，再画关系、差别与指称锚，处理改名、拆分、合并和修复，配套误并误拆读数、申诉通道与停止条件。

== 这套方法解决什么问题
这套方法用于数据治理、档案、项目管理、组织交接、产品账号和人工智能实体识别中反复出现的身份难题：两条记录是否指向同一对象，一条记录变化后是否仍延续，两个对象合并后旧责任怎样追踪。它不替代身份证明、司法认定或专业领域标准，而是把容易混在一起的判断拆开，让团队知道争议究竟发生在哪一层。

最小试点选一类经常误并或误拆、但不直接决定高风险权益的对象，抽取二十个已复核案例。建立对象卡，写明对象层级、关系材料、区分条件、当前名称、允许变化和撤回入口。先复现旧系统结论，再用新卡重判，比较分歧来自材料不足、规则冲突还是名称误导。

项目输出不追求一个万能身份分数，只交付身份规则、边界案例、版本记录和纠错路径。任何自动合并都保留原记录，任何拆分都保留关联历史。若团队无法说明回退办法，不启动批量处理；身份工程首先是可纠错工程。

启动人还要写清谁承受误并、谁承受误拆，以及两类伤害的优先级。若收益归平台、纠错成本全给当事人，试点设计不合格。先调整责任和资源，再谈识别精度。

== 先定位：问题究竟卡在哪一环
把流程分为对象选定、材料采集、差别提取、关系连接、名称绑定、连续判断、使用与纠错七环。争论“是不是同一个”前，逐环标记证据。若有人在讨论账号、有人在讨论账号背后的人，卡在对象选定；同名被自动合并，卡在名称绑定；换设备后被判新用户，可能卡在连续判断。

用一次真实错案沿时间线回放：最早何时出现候选，哪项材料把它们拉到一起，哪条规则完成合并，谁在何时发现错误，系统能否撤回。第一次从材料走向错误结论的箭头，就是首要卡点。不要同时改全部七环，否则效果无法归因，旧错误还可能换一种表面继续存在。

定位后写一句可观察目标，如“同名不同人的自动合并下降且人工复核量不翻倍”，而不写“建立统一身份”。对象层级与用途随版本保留，禁止后来用同一身份号支持未经评估的新用途。新用途改变了判断代价，应重新定位，而不是继承旧规则的权威。

每个卡点只指定一个负责人和一个复核日，材料所有者与决策者分开。若修复后错误移到下一环，更新定位并保留旧结论，不用总体准确率把问题冲淡。

== 先划清人与记录的安全边界
涉及个人、未成年人、健康、亲密关系、救助资格、就业或其他权力不对称场景时，本方法不得自行判定法定身份、可信度、诊断或资格，也不得减少既有支持。先遵守适用法律、伦理、专业与机构程序，取得必要授权和真实可行的拒绝方式。试点优先用去身份案例或非关键对象。

一条记录不是一个人，系统没有匹配到也不等于当事人不存在或陈述虚假。禁止把低匹配分自动转成惩罚、拒绝服务或风险标签。高风险决定必须有人复核，向受影响者说明用了哪些材料、怎样更正、由谁受理申诉，并在争议解决前采取不造成额外伤害的临时安排。

建立权益卡：用途、最低必要字段、保存期限、访问角色、自动化边界、人工复核者、申诉时限和紧急停止人。供应商模型也受同一限制，不能以商业秘密取消基本说明。若无法给当事人有效更正路径，停止将身份系统用于真实权益决定。

任何测试材料都不得被悄悄转入生产画像、营销或风控。试点结束按权益卡删除，不因“以后也许有用”无限保存。发现泄露、越权访问或错误标签传播时，立即冻结接口并启动通知与补救。

== 先说清正在识别哪个对象
同一个业务页面可能同时出现人、账号、设备、订单、文件和项目六类对象。先为每条规则写一个主语：“本规则识别的是一次申请”“本规则延续的是项目版本”。禁止只写“用户身份”，因为同一人可以有多个账号，同一账号也可能由组织多人操作，设备变化更不能直接等于人的变化。

对象卡至少列边界、起点、终点、允许的组成变化和不得继承的属性。订单合并不自动合并付款责任，文件复制不自动复制授权，部门改名不自动抹去旧承诺。每个属性都注明属于哪一层，系统查询时先选对象层级，再返回名称和关系，避免跨层偷渡。

用三问测试定义：它能否处理同名不同物，能否处理同物改名，能否处理一物拆成两物。任一问题只能靠人工猜测，就补规则或承认未知。对象边界宁可窄而清楚，不要为了一个全局编号把不同责任强行压成同一东西。

再用一条自然语言例句验证每个对象，如“这次申请在改地址后仍是同一次申请”。业务、技术和权益人员若对主语指向不同，就暂停建模，先统一对象词典与反例。

== 画出让对象持续成立的关系
为目标对象画关系表，不先画外观特征。项目可包括发起人、目标、合同、资源、版本和交付；数据文件可包括来源、生成过程、权限、内容摘要和后续派生；账号可包括创建、验证、使用、恢复和授权事件。每条关系写来源、时间、可信范围与可更改性。

关系不是越多越好。选择与当前用途有关、来源相对独立且能改变判断的材料。多个字段若都复制自同一旧表，只算一个来源；同一错误经不同系统回流，不能伪装成多方印证。用来源图标出共同上游，防止“证据很多”其实只是同一录入被重复显示。

每次判断至少保留一条连续关系和一条排除竞争对象的关系。前者说明为什么仍是它，后者说明为什么不是旁边那个。若只能找到支持关系、找不到排除材料，输出候选而非确定身份。关系表随真实事件更新，旧版本不可覆盖删除。

对高代价决定，还要有一条不依赖主数据库的复核来源，避免数据库自身错误循环证明自己。若独立来源不可得，降低确定度并扩大人工解释，不用更多同源字段替代独立性。

== 把差别写成可核对条件
差别用于让候选从背景中浮出。把“看起来不一样”改成字段与阈值，例如时间区间不重叠、来源链不同、关键内容冲突、授权主体不同。每项差别写它能排除什么、不能排除什么，以及技术变化会不会让它失效。姓名拼写差异通常弱，独立来源和不可同时成立的事件通常更强。

差别也会被复制、伪造或自然变化。设备号可能更新，地址可多人共用，生物特征也可能受采集条件影响。不要把任何单字段设为永久本质；为关键差别配第二来源，并设置人工复核区间。系统应能输出“不足以区分”，不能为了完成率强制二选一。

每季度抽取被合并案例中的冲突材料和被拆分案例中的连续材料，检查差别权重是否反向工作。若某差别只在一类群体上产生大量冲突，要排查采集偏差和结构性不利，而不是给该群体加更严格证明负担。

差别规则设有效期，技术、业务或社会条件变化时重新验证。曾经稀有的特征可能后来普及，曾经稳定的地址可能因灾害或迁移失效；过期条件自动降级为线索，不继续充当唯一判据。

== 建立可以负责的指称锚
指称锚是团队用来再次找到对象的入口，可以是受控编号、版本地址、登记名称或经过授权的组合键。它必须唯一到目标层级、可追踪创建者、与关系材料相连，并能在错误时撤回。随机编号通常比姓名稳定，但编号本身不证明所指正确。

创建锚时记录绑定依据、时间、执行者和置信状态；调用锚时返回对象层级和当前状态，不能只吐出号码。若锚被复制到别系统，连同用途限制与版本一起传递。外部系统无法承载限制时，不做静默同步，改为受控查询或明确的低可信映射。

锚的治理包括改名不换对象、对象变化换版本、错误绑定撤销、历史查询与别名管理。禁止删除旧锚后重建同号来“清理数据”，因为这会让两个时期的责任混在一起。一个好锚减少寻找成本，却不垄断最终解释权。

定期做锚碰撞测试：随机取一批号码，确认不会同时指向两个活动对象；再取已停用号码，确认系统不会误分配给新对象。发现碰撞先冻结写入，沿创建日志定位源头，不能靠覆盖其中一条记录消除报警。

== 分开名字、号码与对象
为每个对象设置内部稳定锚、展示名称和外部号码三个字段。展示名称可变，外部号码可能由别机构回收或改版，内部锚只在本系统对象边界内稳定。任何匹配规则不得因为名称相同直接合并，也不得因为名称不同直接拆分；它只能触发关系复核。

改名流程先验证请求权限，再记录生效时间、旧名查询期、依赖系统和通知范围。涉及个人自我陈述时，展示与称呼应及时尊重更新；历史合规记录按适用规则最小保留，不能借“历史真实性”继续不必要暴露。对象连续与展示方式是两项不同决定。

外部号码变更时建立一对一、一对多或多对一映射，并标明有效期。若无法确定对应，保留未决，不用最近姓名填空。审计随机搜索旧名、当前名和内部锚，确认三条路径回到正确层级且不会泄露无关历史。

界面应明确展示“这是名称相似候选”还是“这是已核验同一对象”，不能用相同颜色和按钮混在一起。人工选择合并前显示会继承的权限、债务和历史，让操作者看见决定后果，而非只看匹配便利。

== 设计变化后的连续测试
连续测试覆盖修复、迁移、重命名、复制、停用后恢复和所有者变更。每类案例事前写“仍是同一”的必要关系与“必须新建”的触发线。例如文件内容小修可沿用版本链，复制到独立目的后应产生新对象；项目更换负责人不必新建，目标和责任整体替换则需复核。

测试时同时放入正例、反例和灰区，不只验证顺手路径。系统对灰区应暂停自动动作，展示冲突材料并交给有权限的人。判断后记录理由码与证据版本，半年后用新结果回看。若灰区几乎全靠同一专家口头决定，规则尚未形成，应缩小自动化范围。

连续不是越多越好。错误延续会把旧债务、权限或污名带给新对象；错误断裂会抹去责任、履历和权益。评估必须同时计算误并与误拆，两者按实际伤害分别加权，不用一个准确率掩盖方向相反的错误。

测试集至少包含一次信息晚到：先依据有限材料判断，再补入关键记录，观察系统能否撤回并传播修正。只会生成结论、不会更正下游的系统，即使首次准确率高，也不适合承担持续身份。

== 处理拆分、合并和复制
拆分时先确定哪些关系属于整体、哪些可分配、哪些必须共享历史。新对象获得新锚，旧对象标记状态但不删除，所有继承规则逐项说明。合并时保留来源对象与冲突字段，设主记录不等于宣告其他历史为假；若合并可逆，记录回退脚本与通知对象。

复制与迁移最容易被误当同一。备份可能只是原对象的恢复材料，分叉副本则会形成独立变化。用“是否独立接受后续动作、是否承担不同责任、是否可能再次合并”三问分类。只看字节相同会漏掉关系变化，只看存储位置不同又会把普通备份切碎。

每次批量操作先做小样本影子运行，不修改生产锚。由业务、数据与权益负责人共同抽查边界案例，再逐批执行。操作后核对下游权限、账务、通知和搜索索引，避免主库正确而外围系统仍沿用旧身份。

为每批设置最大影响量、自动停线阈值和抽样比例。若误并、误拆或申诉在任一批超过阈值，停止后续批次并回退本批。批量脚本、参数和审批单一起留档，保证错误可定位而非只剩结果。

== 在组织交接中保住项目身份
组织重组时，项目名称、团队和负责人常同时变化。先把项目身份落在目标、承诺、资源、决策记录和交付关系上，再判断哪些变化仍属连续。不要只因团队改名就关闭旧责任，也不要只因编号沿用就假设使命未变。交接卡应列未完成承诺、解释权、版本位置和争议事项。

原负责人和接手者分别独立描述“这个项目是什么”，对照差异。若双方只共享名称、不共享目标与责任，连续性可能只是表面；若名称全变但承诺与决策链清楚，仍可保持同一项目。分歧由项目所有者裁定，并向受影响者说明哪些责任延续、哪些重新授权。

交接后设置一次真实边界任务，观察接手者能否用记录处理未预设问题。只会重复旧模板说明资料保留了外壳，没有交接判断。结果用于补流程与权限，不用来羞辱个人；关键服务设置并行期和回退负责人。

并行期结束前向项目受影响者发出一份责任清单，说明新入口、旧承诺和争议处理人。若接手者没有修改过任何记录的权限，交接仍只是代理执行；应补足有限改版权并保留监督。

== 在数据与人工智能中限制自动认同
实体匹配模型只输出候选、分数和支持材料，不直接输出“就是同一个人”的绝对事实。按用途设置不同阈值：推荐去重可容忍的错误，不能直接搬到福利、招聘、执法或健康场景。高风险用途需要独立评估、人工复核、影响说明和可执行申诉。

训练与测试集按时间、来源和群体切分，防止同一上游记录同时出现在两边造成虚高。除总体误并误拆外，报告群体差异、未知率和复核负担。若提高阈值只把证明成本推给数据较少者，应增加替代材料入口，而不是宣称模型对所有人一视同仁。

模型版本更新不自动覆盖旧结论。保存当时模型、输入摘要、规则和人工决定，允许后来重新评估。禁止为提高匹配率无限收集生物、位置或关系数据；先证明新增字段确实改变必要判断，再做隐私与安全评估，设删除日期。

上线前用“同名不同人、同人多账号、共享设备、数据缺失、恶意冒用”五类压力案例测试。模型无法稳定说明主要证据时，只能做检索排序，不进入合并动作。供应商更换也须重测，不能继承旧认证。

== 读数、采集办法与代价
核心读数包括误并率、误拆率、未知率、人工复核量、申诉改判率、纠错时长、下游残留错误、按群体分解的差异和每次批量操作回退次数。样本来自已复核争议、随机抽检和合成边界案例，不能只用系统自动确认的“真值”验证自己。

每项读数附分母、用途、采集频率和删除日期。个人数据按最少必要原则采集，能用事件摘要就不保存原文，能用去身份案例就不保存身份。不同来源分别计数，防止同一错误回流成多项证据。报告未知与缺失，不把未申诉者默认为无错。

代价包括复核延迟、规则维护、错误关联造成的权益伤害、过度拆分造成的服务中断，以及为匹配而扩张监控。将伤害成本与技术成本同时列入决策。若新增字段没有显著减少高代价错误，删除字段而不是继续调权重。

读数看板不得展示个人或小群体可识别信息，也不做团队竞赛。每季度随机回访一小批已纠错案例，确认下游确实清除；若申诉改判率下降同时未知率激增，不能宣称质量改善，只是系统少作决定。

== 复核、申诉与版本责任
每个身份决定都要有可读理由：识别的对象层级、采用的关系、关键差别、使用的锚、规则版本和人工责任人。受影响者能够查看与自己有关的必要信息、提出更正并获得时限内回应。不能因申诉而降低服务或增加惩罚性标记。

复核者不应是原决定唯一制定者。高风险案例由业务与权益角色共同看，技术人员解释模型而不替代价值判断。改判后不仅修主记录，还要寻找下游副本、缓存和报告；建立传播清单，直到残留错误被关闭。无法追回的披露应告知适当责任人并采取补救。

版本记录保存规则变化的理由和适用范围。新规则不默认追溯重写全部历史，也不因旧规则曾有效就拒绝重审重大伤害。每季度从申诉中挑选一种系统性错误，修改上游流程；若申诉永远只修个人，系统没有学习。

设置申诉服务标准：确认收到、给出材料、完成初审和告知结果各有时限。逾期自动升级，复杂案件可延长但须说明。复核结果既能维持原判，也能标记未知，不能为了结案率强迫确定。

== 什么时候应该停，什么时候说明理论可能不对
出现未经授权的数据扩张、误并导致权益受损、自动系统越过人工边界、未成年人或弱势群体承担额外证明负担、无法回退批量变更时，立即停止并恢复安全版本。涉及司法、医疗、救助等决定，转由具备权限的专业程序，不拿本方法补授权缺口。

若内部单一特征在目标领域始终唯一、稳定且足以决定身份；加入关系、差别和指称锚没有减少误并误拆；三类动作不能产生可区分的失败；或对象层级化只增加成本而不改善任何边界判断，那么母文框架在该用途不成立，应改用更简单规则。

试点连续两轮没有减少高代价错误，或复核成本超过预设上限，也应结项。报告保留哪些普通数据清理有效、哪些理论判断被削弱、哪些仍未知，删除无必要个人数据。重启必须有新材料、新用途评估和新授权，不能沿用旧试点无限延长。

若简单的唯一键加人工复核已经达到相同效果，就采用简单方案，不因框架完整而制造复杂系统。停止不是失败掩盖，而是对证据边界负责；结项后仍保留申诉入口，直到旧决定的影响期结束。
