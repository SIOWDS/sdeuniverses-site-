# 三位一体出版单元（阅读 · 学习包 · 智能问对）

> 状态：**本地候选 + 离线/浏览器替身测试通过**。未部署生产；未做真实模型验收；未验证任何学习效果。

## 一、理论：为什么是"问题节点"

一本专著过去是三个互不相识的东西：**原文**（给依据）、**学习包**（留过程）、**智能体**（接追问）。
三者各有一个"读者"和一场"对话"，读者在其中任一处做的事，另外两处看不见。

出版单元的做法是只立一条连接线：**问题节点**（`unitId` + `nodeId`，如 `m3` + `P1`）。

- **原文**回答"书怎么说"——每个节点带原文锚点；
- **学习包**回答"我怎么想、怎么变"——初答、复答、对照、迁移，追加保存；
- **智能问对**回答"还能怎么追问"——按任务（提示/比较理解/检验异议/迁移/回看/小结）接续同一节点。

读者的一次完整往返：**封存初答 → 带问阅读 → 复答/异议 → 明确任务的问对 → 登记未核对建议 → 本人确认修订 → 迁移与观察 → 回看。**
可往返、可停、可不赞同；"不知道""尚未实施""理解后仍反对"都是合法状态。不把"理解""赞同""迁移"合成一个分数。

## 二、四条硬合同

1. **模型不替读者确认任何东西。** 回答只登记为"未核对建议"；采纳/修改/反对/暂不判断/独立修订只有读者点击才产生，且要读者自己的话（暂不判断除外）。
2. **两次确认。** ①发送前预览：显示将发出的每一份个人文字，逐项勾选，默认只勾任务必需项；材料一变，指纹变，旧确认失效。②修订时本人确认。
3. **完整性可信。** 回执只有 `complete / interrupted / cancelled / error`；"有文字"不等于完成。**不完整的回答不能被采纳**，只能作草稿或写独立修订。
4. **历史只追加、不裁剪。** 账本达上限时拒绝写入并提示导出，绝不静默删旧记录；初答每节点只封存一次；导入遇同号不同内容、跨书、两份不同初答，整批拒绝。

## 三、数据与代码

| 对象 | 位置 |
|---|---|
| 内核（账本/预览/回执规则） | `public/books/unit/unit.js`（纯逻辑，浏览器与 Node 共用） |
| 每书单元清单（只记事实） | `public/books/m/N/unit.json`（`tools/build_unit_manifest.py` 生成） |
| 学习包（问题节点、原文锚点、对照答案） | `public/books/m/N/learn.json`，页面 `/books/learn/?b=N` |
| 智能问对（任务路由、预览、回执、修订） | `public/books/agent/app.js` 的"三位一体"段；入口 `/books/m/N/agent/?node=P1&task=hint` |
| 服务端任务块 | `src/worker.js` 的 `UNIT_TASKS` / `unitBlock()`，仅 `b.bookagent` 且带 `b.unit` 时生效 |
| 账本存储 | 浏览器 `localStorage` 键 `wds_unit_<书号>`；**只在本机，不是云备份** |

账本事件：`seal`（初答封存）· `prepared` · `sent` · `receipt` · `revision` · `observation` · `objection`。
同名节点（如 `P1`）在不同书里互不串档（键含书号）。

### 隐私边界（如实）
- 个人文字默认不发；发送时模型 Key 与勾选内容**经本站接口转发**给模型服务商。页面原来"Key 不上传本站"的说法不准确，已改。
- 单元模式不带普通聊天历史（`history:[]`）。
- 材料中的"忽略以上规则"之类句子只作为待分析文字，服务端明示不执行（有测试）。
